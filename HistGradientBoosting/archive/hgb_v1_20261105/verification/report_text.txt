Data 处理边界
本方案保留原始 sales records；没有另外做 outlier removal、winsorization、price clipping、scaling 或 mean/median imputation。garage 大于 parking_total 的记录保留原值并添加 flag，不自动纠正。Lot structural missing values 保留为 NaN。
主要实现位置为 code/data.py 和 code/features.py。所有 fold 的 preprocessing 都只在各自 training rows 上学习，未用 future rows 预先确定 category levels。

Estimator 与 target restoration
本方案使用 scikit-learn 1.7.2 的 HistGradientBoostingRegressor。Histogram-based gradient boosting 将连续 features 分桶，在后续 iterations 中逐步修正 transformed-target loss。HGB 支持 numeric missing values 和 native categorical splits；这里同时比较了 OneHot 与 native encoding。[E1]

Off-market
z = ln(sold_price)
f(X) approximates z
predicted_log_price = f(X)
predicted_price = exp(f(X))
最终采用 native categorical encoding。每次 fit 从 training rows 的 observed nonmissing values 建立 pandas Categorical levels；predict 沿用保存的 levels，unseen category 转为 missing。每个 categorical column 的 cardinality 必须不超过 max_bins=255，否则报错。
Final training 的四项 category counts 分别为 house_type_name 6、house_style 16、municipality 5、community 145。Estimator 接收18个 columns，即14个 numeric/binary 与4个 categorical columns。

List-aware
z = ln(sold_price) - ln(list_price)
g(X) approximates z
predicted_log_price = ln(list_price) + g(X)
predicted_price = exp(predicted_log_price)
list_price 同时是 numeric feature 和 restoration offset。Training 与 inference 的 list_price 必须 positive finite。两个 tracks 的 predict_log() 都返回最终 log(price)；只有 List-aware raw estimator.predict() 返回 log ratio。不要将它直接当作 log price。
最终采用 dense OneHot matrix。Numeric features passthrough；OneHotEncoder 使用 handle_unknown="ignore"、sparse_output=False、drop=None、dtype=float64、categories="auto"。Unseen category 的对应 block 全零。ColumnTransformer 使用 remainder="drop" 和 sparse_threshold=0.0。Final estimator 接收187项 features，即15个 numeric/binary 与172个 indicators。
OneHot 的 max_categories 和 min_frequency 均为 None，feature_name_combiner="concat"。虽然 estimator 参数仍记录 categorical_features="from_dtype"，该输入已是 numeric matrix，因此实际没有 native categorical splits。

Objective 与 output
每个 fit 使用完整过去 history、equal sample weights，以及 transformed target 上的 squared_error。Selection 使用 raw-price pooled MdAPE，二者是不同 objective。本版本没有 smearing correction 或 posthoc calibration；predict() 输出同输入顺序的一维 positive finite array。Metrics 使用 unrounded prices，submission 使用 numpy.round(price)。

Model selection 与 experiment accounting
Development 使用 Jun–Nov 2025 的六个 temporal folds。每个 fold 只使用 validation month 之前的 sales。November 曾用于早期 algorithm probe，因此整个 development 明确属于 adaptive selection。
Stage | 测试内容 | 新增 physical fits
A Reference | 2 tracks × 2 encodings × 6 folds；200 iterations，31 leaves，min leaf20。 | 24
B Capacity | 每个 track/encoding 比较 leaves {15,31,63} × min leaf {20,50}。A结果在B中复用。 | 120
C Iterations | 每个 track/encoding 保留一个 capacity；每fold从头fit800，评估100/200/400/800 checkpoints。 | 24
D Target | 只对选中的 List-aware config 比较 log_price 与 log_ratio。 | 6
Development total | Capacity grid 含A为144fits；加C与D。 | 174
Rolling backtest | 2 tracks × 6 monthly refits。 | 12
Horizon backtest | 2 tracks，各固定cutoff只fit一次。 | 2
Final fit | 2 tracks，各使用全部150,000 sales。 | 2
Original formal total | 不含 unit-test fixtures 或本次 archive replication checks。 | 190
C阶段的24次 fits 产生96组 checkpoint fold evaluations，不能将它们重复计为96次 physical fits。每个 staged200 checkpoint 都与独立200-iteration fit 检查 row identity 和 predictions allclose。Training、recent-training 与 future metrics 均使用同一 checkpoint。

Selection rule
在六个月全部 evaluation rows 上 pooled 计算 raw-price MdAPE，取最小值；依次以 MAPE、较少 leaves、较少 iterations、较大 min_samples_leaf、OneHot优先于native、log_price优先于log_ratio作为 tie breakers。每个 track 最终统一选择一个 iteration count，不为每fold单独选最佳 checkpoint。
Off-market 选 native / 63 leaves / min leaf20 / 800 iterations，development MdAPE为8.8637%。List-aware 选 OneHot / 63 leaves / min leaf50 / 400 iterations；将target从log_price改为log_ratio后，development MdAPE从4.3170%变为4.2639%。这是该config下的 ablation，不能单独证明ratio在所有models上更好。
Config 于 2026-11-03 01:33 UTC 冻结，本版本新 backtest scores 未参与冻结选择。Search 属于 budget-limited sequential procedure，未联合穷举全部 capacity 与 iterations；Off-market 的63 leaves和800 iterations位于测试grid上界，不能称为global optimum。

Rolling protocol：evaluation month为M时，training条件为date_sold < M的第一天，validation为date_sold属于M。每个月重新fit。每个track pooled development n=12,169，rolling n=10,069；两个tracks使用相同validation IDs与truth。
Horizon protocol：两个tracks分别只fit一次，固定training cutoff为2026-02-01，training n=142,227；同一个model预测Feb–May2026，pooled n=7,773。Horizon index依次为1至4。它更接近固定model一次预测未来数月的submission场景。
Rolling包含Dec–Jan而horizon不含，不能将两者pooled metrics之差全部归因于model更新频率。若要隔离更新效果，应比较共同Feb–May cohort。

Metrics
signed_error_i = 100 * (prediction_i - actual_i) / actual_i
APE_i = abs(signed_error_i)
MdAPE = median(APE_i)
MAPE = mean(APE_i)
Median signed error = median(signed_error_i)
Log-price MSE = mean((ln(prediction_i) - ln(actual_i))**2)
所有price metrics以percentage呈现；median signed error为正表示偏高估、负表示偏低估。Pooled MdAPE直接在所有evaluation rows上取median，并非monthly MdAPE的平均。100 − MdAPE不是classification accuracy。
Reused表示这些periods在此前RF/Bagging评估中已被观察过。各fold仍不使用未来sale labels；但它们不再是untouched tests。此外，本protocol是sale-month evaluation，不是严格listing-day valuation：部分房屋可能在training cutoff前已经挂牌。
